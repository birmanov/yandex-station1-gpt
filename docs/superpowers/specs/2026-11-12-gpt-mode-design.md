# GPT-режим Станции 1: дизайн

Дата: 12 ноября 2026. Статус: предложение, не реализовано.

## 1. Цель и границы

Владелец нажимает «GPT» на странице веб-пульта, задаёт вопрос голосом через микрофоны Станции, слышит ответ через её динамики, после чего Алиса снова отвечает как обычно.

Решения, принятые при обсуждении:

- **Всё в облаке, без своего сервера.** Станция сама вызывает OpenAI: распознавание, ответ и синтез. На ПК ничего не крутится.
- **Один провайдер — OpenAI**, один ключ. LLM — тоже OpenAI (не Claude).
- **Запуск — кнопка в веб-пульте.** Карточка Projectivy и клавиша физического пульта — следующие этапы, здесь не рассматриваются.
- **Модуль внутри `StationRemote`** (вариант A): тот же процесс, та же авторизация и сборка. Отдельный демон не создаётся.

Не входит в этот этап: постоянное прослушивание, голосовая команда переключения, непрерывный диалог без кнопки, Realtime API.

## 2. Компоненты

Новый код — в `experiments/gpt-mode/src/`, компилируется `--release 7`, без библиотек (как пульт). До проверки на устройстве не переносится в `remote/`.

| Класс | Ответственность | Зависит от |
| --- | --- | --- |
| `GptSession` | Единственный владелец состояния и потока выполнения одного вопроса; таймауты; отмена; возврат Алисы | `AudioIn`, `AudioOut`, `OpenAiClient`, `AliceControl`, `GptConfig` |
| `AudioIn` (интерфейс) | `byte[] record(int maxMillis, Cancel cancel)` → PCM 16 кГц, 16 бит, моно | — |
| `AudioOut` (интерфейс) | `void play(byte[] pcm, int sampleRate, Cancel cancel)` | — |
| `AndroidAudio` | `AudioIn`+`AudioOut` через hidden API `android.media.AudioRecord`/`AudioTrack` по reflection, по образцу `Input` в пульте | Android API 23 |
| `AlsaAudio` | `AudioIn`+`AudioOut` через подпроцессы `tinycap`/`tinyplay`. Прямая работа с `/dev/snd` в этот этап не входит; если бинарей на прошивке нет, спайк фиксирует это и `AlsaAudio` остаётся нереализованным | ALSA устройства Станции |
| `OpenAiClient` | Три вызова REST; multipart и JSON вручную; таймауты; один повтор при сетевой ошибке | `HttpsURLConnection`, `TrustStore` |
| `TrustStore` | `SSLSocketFactory` по умолчанию, а при отсутствии корня на Android 6 — доверие CA из файла `openai-ca.pem` рядом с конфигом | — |
| `AliceControl` | Освободить микрофон/звук для GPT и вернуть их Алисе; реализация выбирается спайком (см. §8) | root-команды |
| `GptConfig` | Чтение `gpt.properties`, права 0600, значения по умолчанию, ключ никогда не возвращается наружу | `restrict()` из пульта |
| `WavCodec` | PCM → WAV для загрузки; разбор `pcm`-ответа TTS | — |

Точка входа в пульте: обработчик `/api/command` с `action=gpt` и `/api/state`, расширенный полем `gpt`.

## 3. Состояния и поток

```
idle ──start──▶ listening ──(тишина | лимит | stop)──▶ thinking ──▶ speaking ──▶ idle
  ▲                 │                                      │            │
  └───── cancel ────┴──────────────── cancel / error ──────┴────────────┘
```

- `start` из `idle`: `AliceControl.acquire()` → `listening`. Повторный `start` в любом другом состоянии — `409`.
- `listening`: запись до `maxRecordSeconds` (по умолчанию 15) или до 1,2 с тишины после начала речи (порог RMS из конфига), или до `stop`. Если речи не было вовсе — `idle` с сообщением «Ничего не услышал».
- `thinking`: `transcribe` → `chat` с историей последних `historyTurns` (по умолчанию 6) пар реплик → `speak`. Любой шаг с таймаутом (STT 20 с, chat 30 с, TTS 20 с).
- `speaking`: воспроизведение; `stop` прерывает.
- Выход из любого состояния, успешный или нет: `AliceControl.release()` в `finally`. Общий сторожевой таймаут сессии — 90 с, после него принудительная отмена и `error`.
- `reset` очищает историю диалога (начать новый разговор), доступен только из `idle`.

Команды пульта: `action=gpt&op=start|stop|cancel|reset`. Все — POST с сессией и CSRF, как остальные команды.

Состояние в `/api/state`:

```json
"gpt": {"configured": true, "state": "speaking", "question": "…", "answer": "…",
        "error": "", "since": 1731400000000}
```

`question`/`answer` — последняя пара; текст ответа ограничен 2000 символами при показе.

## 4. Вызовы OpenAI

| Шаг | Эндпоинт | Параметры по умолчанию (меняются в конфиге) |
| --- | --- | --- |
| STT | `POST /v1/audio/transcriptions` | `model=gpt-4o-mini-transcribe`, `language=ru`, `response_format=json`, файл `question.wav` |
| LLM | `POST /v1/chat/completions` | `model=gpt-4o-mini`, системный промпт «кратко, по-русски, без разметки, до 3 предложений», `max_tokens=300` |
| TTS | `POST /v1/audio/speech` | `model=gpt-4o-mini-tts`, `voice=alloy`, `response_format=pcm` (24 кГц, 16 бит, моно) |

`pcm` выбран намеренно: на Java 7 без библиотек нечем декодировать MP3/Opus, а `AudioTrack` и ALSA играют PCM напрямую.

Авторизация — заголовок `Authorization: Bearer <ключ>`. Ошибки: `401` → «Ключ отклонён» и `configured=false` не меняется (ключ не стирается); `429`/`5xx` → один повтор через 2 с, затем ошибка; сетевой сбой → ошибка. Во всех случаях — `release()` и `idle`/`error`, Алиса возвращается.

Журнал (`server.log` на устройстве): только шаг, код ответа и длительность. **Никогда**: ключ, тело запроса, текст вопроса/ответа, аудио.

## 5. Конфигурация и секреты

Файл `gpt.properties` в корне пульта (`/data/station-remote/`), права 0600 через тот же `restrict()`, что и сессии:

```properties
openaiKey=            # обязателен; никогда не пишется в ответы API и журнал
audio=android         # android | alsa
alsaCaptureDevice=    # только для alsa, формат hw:0,1
alsaPlaybackDevice=
maxRecordSeconds=15
silenceMillis=1200
silenceRms=600
historyTurns=6
sttModel=gpt-4o-mini-transcribe
chatModel=gpt-4o-mini
ttsModel=gpt-4o-mini-tts
ttsVoice=alloy
systemPrompt=Ты голосовой помощник. Отвечай по-русски, кратко, не больше трёх предложений, без списков и разметки.
```

Ключ задаётся двумя путями: файлом по SSH или формой на странице пульта (`POST /api/gpt/config`, сессия + CSRF; поле ключа write-only, страница видит только `configured`). `.gitignore` дополняется `gpt.properties*` и `openai-ca.pem`.

## 6. Страница пульта

В `index.html` добавляется блок «GPT»: кнопка «Спросить», превращающаяся в «Стоп» в `listening`/`speaking`; индикатор состояния (цвет + текст); последние вопрос и ответ; кнопка «Новый разговор»; свёрнутая форма ключа. Состояние берётся из уже существующего опроса `/api/state`; новых WebSocket-сообщений не вводится.

## 7. Тестирование

**На ПК (JDK 17, `--release 7`, без Android):**

- `WavCodec`: заголовок WAV, длина, разбор PCM.
- `OpenAiClient` против локального HTTP-сервера-заглушки на `127.0.0.1` (клиент принимает `baseUrl`, для тестов `http://`): корректность multipart и JSON, обработка `401`/`429`/`5xx`/таймаута, отсутствие ключа и тел в журнале.
- `GptSession` с фальшивыми `AudioIn`/`AudioOut`/`OpenAiClient`/`AliceControl`: переходы состояний, `stop` на каждом этапе, `cancel`, сторожевой таймаут, гарантированный `release()` при исключении на каждом шаге, лимит истории.
- `GptConfig`: значения по умолчанию, права файла (проверка через `android.system.Os` на устройстве, `SKIP` на ПК), ключ не попадает в `toString`/state.

Реальный вызов OpenAI в тестах не делается; для ручной проверки — отдельный режим `OpenAiSmoke` с ключом из переменной окружения, результаты в репозиторий не попадают.

**На устройстве:** спайк из §8, затем сквозной прогон: вопрос → ответ → Алиса отвечает после. Запись разговоров в репозиторий не ведётся.

## 8. Спайк на устройстве (предпосылка реализации аудио)

Нужен root SSH с этого ПК. Вопросы и критерии:

1. **Запись:** `AudioRecord` через `app_process` даёт разборчивую речь с нужных микрофонов? Если нет — `tinycap`/`/dev/snd` при остановленном процессе Алисы? Результат: выбранный `audio=` и устройства.
2. **Воспроизведение:** `AudioTrack` слышен через динамики при работающей Алисе? Если нет — что нужно освободить/остановить? Результат: содержимое `AliceControl`.
3. **Возврат Алисы:** после эксперимента Алиса отвечает на голос без перезагрузки? Результат: процедура `release()`.
4. **TLS:** `HttpsURLConnection` к `api.openai.com` без ошибки сертификата? Если нет — какой корень нужен в `openai-ca.pem`.

Каждый пункт — команды запуска/остановки, фактический результат и откат; фиксируется в `experiments/gpt-mode/SPIKE.md` без личных данных и адресов. Аудиозаписи удаляются с устройства после проверки.

## 9. Безопасность

- Все GPT-команды — только с сессией и CSRF пульта; HTTP остаётся локальным.
- Ключ только в `gpt.properties` 0600; ошибка ограничения прав — отказ в сохранении, как у сессий.
- Микрофон включается только по команде и на ограниченное время; состояние видно на странице.
- Любой сбой заканчивается `release()`; Алиса не остаётся без звука.
- В Git не попадают ключ, CA-файл, записи, журналы устройства.
