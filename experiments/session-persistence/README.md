# Эксперимент: сохранение входа в веб-пульт

> **Незавершённый снимок. Не развёрнут на устройстве, не является готовым или проверенным безопасным обновлением.**

Здесь отдельно сохранены текущий локальный кандидат `StationRemote.java` и тест `SessionPersistenceCheck.java`. Они не участвуют в обычной сборке `remote/build.py`. Общая зависимость `VlessLink.java` находится в `remote/src/`.

Цель: сохранять вход на 30 дней и восстанавливать сессии после перезапуска службы, не убирая пароль, CSRF и проверку Origin.

## Что известно о проверках

Предшествующая версия кандидата прошла базовые сценарии на Android, включая создание и восстановление входа в разных процессах. Проверены последовательные выход и смена пароля, отказ при неверном CSRF/Origin и закрытый режим при повреждённом хранилище.

Независимая проверка затем нашла блокирующие замечания:

- Гонка между сменой пароля, проверкой старого пароля и выдачей/сохранением сессии.
- Необходимость проверять результат ограничения прав на каталог и файлы с токенами.
- Несогласованность памяти и диска при ошибке записи отзыва сессии, которая может привести к её восстановлению после перезапуска.

Дополнительная доработка была прервана. Этот снимок может отличаться от версии, для которой ранее прошли тесты. **Старые результаты нельзя автоматически приписывать текущему коду.**

До выпуска нужны целевые конкурентные тесты и проверки ошибок записи/отзыва, полный повторный прогон и независимая проверка. Эксперимент нельзя автоматически подставлять вместо установленного сервера.

## Изоляция тестов

Тестовые пароли с префиксом `fixture-` — вымышленные данные, не пароль владельца. Тесты создают отдельные каталоги `/data/local/tmp/remote-session-*`. Нельзя менять их на каталог действующего пульта или читать реальные файлы авторизации для проверки.

Тест требует Android API и root-контекст для инициализации управления, а не только обычную настольную JVM. Перед запуском нужно отдельно собрать кандидат и тест для API 23, соблюдать ограничение памяти и закрыть тестовые процессы. На Android 6 использовать свежие имена JAR при изменении класса, чтобы не принять старый ART-кэш за ошибку исходников.

Происхождение базового кода и лицензия описаны в `../../THIRD_PARTY.md`.
